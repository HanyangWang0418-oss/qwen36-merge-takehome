## Research question

Can three domain experts, each a LoRA on the frozen `Qwen/Qwen3.6-35B-A3B` base,
be merged into one adapter that beats the base on all of SWE-bench Pro v2-hard,
Terminal-Bench 2.0, HLE and ASI-Bench, and which merge rule (additive task
arithmetic vs. sign-elected TIES, with or without DARE dropout, with or without
layer scoping) loses the least per benchmark?

**Expert split** (`configs/experts/`): by task form, not strictly one per benchmark.

| expert | target | why this split |
|---|---|---|
| e1_code_repair | SWE-bench Pro v2-hard | issue→patch inside a repo; agent loop over files + tests |
| e2_terminal_agent | Terminal-Bench 2.0 **and** ASI-Bench | both are sandbox + shell + produce-an-artifact tasks; sharing data gives ASI (60 projects, few public analogues) a larger pool |
| e3_reasoning | HLE | single-turn long-thinking short answer; no tools |

Controls: 4-expert split (e2 → terminal-only + research-agent), rank 128 vs 32 for e1, and four merge recipes (`configs/merge/`).

## Base model (locked)

`Qwen/Qwen3.6-35B-A3B` — 35B total / 3B active MoE, 40 layers, 256 experts (8 routed + 1 shared), hybrid Gated DeltaNet + Gated Attention, 256K native context, Apache-2.0. Revision, tokenizer and chat-template hash: `data/manifests/base_model.json` (filled by `scripts/lock_benchmarks.py`).

Why 35B and not 7B: training runs on Tinker (managed LoRA; MoE expert matrices are adapted), so the 70 GB bf16 weight footprint is only a serving cost, borne once by one vLLM server shared by all evaluations.

## Benchmarks: versions and splits

See `configs/eval/*.yaml` and the snapshots in `data/manifests/`. Summary:

| benchmark | source | split / size | harness | primary metric |
|---|---|---|---|---|
| SWE-bench Pro v2-hard | `ScaleAI/SWE-bench_Pro` config `hard` | test, 51 tasks (`v2/hard51_ids.txt`) | Harbor + `locked_mini_swe` from `scaleapi/SWE-bench_Pro-os`, 50 min/task, offline agent, fresh-sandbox regrade | resolved rate (regraded) |
| Terminal-Bench 2.0 | Harbor registry `terminal-bench/terminal-bench@<2.0.x>` | all tasks | Harbor + terminus-2, 3 h / 32 CPU / 48 GB, T=1.0 top_p=0.95 top_k=20 max_tokens=80K ctx=256K | success rate, mean ± std over 5 seeds |
| HLE | `cais/hle` test | **text-only subset** (ids in manifest) | official `run_model_predictions.py` + `run_judge_results.py`, judge `o3-mini-2025-01-31`, no tools | accuracy |
| ASI-Bench | `Apexintelligence-AI/ASI-Bench-<track>` | 60 projects × B1–B4 | `asibench` 0.2.0, opencode adapter, docker sandbox | **B3 mean final_score** (fixed before training) |

Same thinking mode (on), preserve_thinking (on for agent benchmarks), bf16, no quantization, same tools and budgets for every model within a benchmark. Deviations from each model card / official setting are listed in the config files under `inference:` and `env_failure_policy:`.

## Reproduction

```bash
uv sync                                   # Python 3.11, pinned in uv.lock / requirements.lock
uv run python scripts/lock_benchmarks.py  # once; commits task-id snapshots to data/manifests/
scripts/prepare_data.sh                   # builds data/processed/*_train.jsonl + manifests
TINKER_API_KEY=... uv run python src/train/train_expert.py configs/experts/e1_code_repair.yaml
uv run python src/train/export_adapter.py tinker://... models/weights/e1_code_repair
uv run python src/merge/merge_adapters.py configs/merge/ta_l0.7.yaml
scripts/serve_vllm.sh                     # on the GPU box
scripts/eval_swebench_pro.sh base base; scripts/eval_terminal_bench.sh base base; scripts/eval_hle.sh base base; scripts/eval_asi_bench.sh base base
uv run python scripts/summarize.py && uv run python scripts/plot_curves.py
uv run pytest -q                          # data-pipeline and merge unit tests
```

## Layout

Follows the template tree with `sft/stage2` replaced by `experts/merged`:

```
configs/{experts,merge,eval,data}/   training, merge, locked eval, data-source configs
data/manifests/                      benchmark snapshots + per-expert data manifests (committed)
data/processed/                      jsonl training sets (gitignored, regenerable)
src/{data,train,merge,eval,analysis} implementation
scripts/                             run commands (see above)
logs/<run_id>/                       metadata.json, metrics.jsonl, resources.csv, train.log(.gz)
curves/ + curves/source/             loss plots and their raw csv
results/{base,experts,merged}/<model>/<bench>/per_task.jsonl, failed_tasks.json, env_failures.json
analysis/                            failures.md (≥20 cases), uncertainty.json, macro_average.json
models/README.md                     HF links, revisions, merge recipes, loading snippet
```

## Known limitations

- HLE is evaluated text-only; no multimodal number is claimed.
- ASI-Bench track (seed42 official vs seed31415 local) depends on interviewer confirmation; recorded in the manifest.
- Tinker does not expose GPU type; training cost is reported in tokens and dollars, GPU-hours only for the serving box.
- Merge ablations beyond the two main recipes are screened on independent proxy sets (`configs/eval/dev_proxies.json`), not on the benchmarks; proxy numbers are never reported as benchmark results.
